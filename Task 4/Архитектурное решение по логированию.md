Задание 4. Логирование

**Мотивация**

Внедрение централизованного логирования необходимо для решения критических бизнес-проблем компании "Александрит". Логирование позволит:

*Технические преимущества:*
- Оперативное выявление и диагностика сбоев в распределенной системе
- Отслеживание полного жизненного цикла заказов
- Анализ производительности и выявление узких мест
- Ускорение расследования инцидентов

*Бизнес-эффект:*
- Снижение процента потерянных заказов
- Улучшение соблюдения сроков выполнения заказов
- Повышение клиентской удовлетворенности
- Сокращение операционных затрат на поддержку

*Приоритеты внедрения*

В первую очередь логирование необходимо настроить для:
1. **MES** - как наиболее критичного компонента, где происходят потери заказов
2. **RabbitMQ** - для мониторинга асинхронной коммуникации
3. **Онлайн-магазин** - для отслеживания взаимодействия с клиентами

**Предлагаемое решение**

[Диаграмма C4 с новыми компонентами плюс логирование](https://drive.google.com/file/d/1zUicZBTO_ez9rmHIetbgfH6VCLE9BiWw/view?usp=sharing)

*Необходимые логи уровня INFO:*

- Изменение статуса заказа: timestamp, order-ID, user GUID, система-источник
- Отправка заказа в MES: order-ID, timestamp, этап обработки в MES
- Расчет стоимости: order-ID, время расчета, количество полигонов модели
- Обработка сообщений RabbitMQ: queue name, message ID, статус обработки

*Другие уровни логирования:*
- **WARN**: Выход параметров за границы нормы (высокая стоимость, большая очередь)
- **ERROR**: Критические ошибки (MES 500, RabbitMQ недоступен, нехватка места)
- **DEBUG**: Контекст для исследования крайних случаев

*Технологический стек:*
- ELK Stack  для сбора и анализа логов
- Grafana для визуализации и алертинга

*Политика безопасности*

- Доступ только через VPN с двухфакторной аутентификацией
- RBAC с минимальными привилегиями
- Маскирование чувствительных данных (имена, контакты)
- Шифрование TLS при передаче и AES-256 при хранении
- Сегрегация логов по индексам в зависимости от чувствительности данных

*Политика хранения*

- **Логи исполнения обязательств**: Хранение до истечения гарантийных сроков
- **Системные логи**: 90 дней
- **Чувствительные данные**: 7 дней
- Ротация логов: ежедневно
- Резервное копирование: ежедневно
- Мониторинг размера: алерты при заполнении 85% объема

**Анализ логов и алертинг**

- Настройка алертов в Grafana Alertmanager:
    - Резкий всплеск нагрузки на компоненты системы
    - Аномальная активность (DDoS-атаки)
    - Превышение времени обработки заказов
- Интеграция с системой инцидент-менеджмента
- Реализация автоматического блокирования IP через Fail2Ban

**Критерии выбора технологии**

| Критерий | ELK Stack | Grafana Loki | Splunk | Datadog |
|----------|-----------|--------------|--------|---------|
| Лицензия | Elastic License | AGPLv3 | Проприетарная | Проприетарная |
| Производительность | Горизонтальное масштабирование | Легковесный | Высокая | Облачное решение |
| Безопасность | TLS, RBAC | OAuth | SOC2, HIPAA | SSO, GDPR |
| Стоимость | Бесплатно | Низкая | Высокая | Зависит от масштаба |
| Интеграция | OpenTelemetry | Prometheus | Универсальная | AWS, Kubernetes |

**Выбор:** ELK Stack как наиболее сбалансированное решение по стоимости, функциональности и возможности масштабирования.
