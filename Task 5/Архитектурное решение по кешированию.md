Задание 5. Кеширование

**Мотивация**

Внедрение кеширования необходимо для решения критических проблем производительности системы "Александрит". Кеширование позволит:

*Решаемые проблемы:*
- Длительная загрузка дашборда MES (основная боль операторов)
- Рост времени обработки запросов при увеличении нагрузки
- Неэффективность существующих оптимизаций (пагинация и фильтрация)
- Жалобы клиентов и партнеров на медленную работу системы

*Объекты кеширования:*
- Дашборд MES со списком заказов
- Новые заказы для операторов
- Результаты расчета стоимости изделий
- Страницы онлайн-магазина с моделями изделий

**Предлагаемое решение**

*Тип кеширования:* Серверное кеширование
*Паттерн:* Cache-Aside

*Обоснование выбора:*
- **Cache-Aside**: Простота реализации (критично при "тушении пожара")
- Подходит для сценариев "частое чтение / редкая запись"
- Не блокирует операции записи в базу данных при высокой нагрузке
- Минимальные риски при некорректной реализации

*Альтернативные паттерны:*
- **Write-Through**: Слишком сложен для текущей ситуации, может замедлить систему
- **Refresh-Ahead**: Требует точных прогнозов нагрузки, высокие риски при ошибках

**Стратегия инвалидации кеша**

Гибридный подход для разных типов данных:

| Компонент системы | Стратегия инвалидации | Обоснование |
|-------------------|----------------------|-------------|
| Список заказов (MES) | TTL 1мин + Инвалидация по событию | Баланс актуальности и производительности |
| Статус заказа | Инвалидация по событию | Критичная информация, требующая мгновенной актуальности |
| Данные API (стоимость) | TTL 5мин | Данные изменяются редко, допустима небольшая задержка |

**Сравнительный анализ стратегий:**

| Стратегия 1 (TTL + События) | Стратегия 2 (Только события) |
|------------------------------|------------------------------|
| **Плюсы:** Баланс актуальности и производительности, автоматическая очистка устаревших данных | **Плюсы:** Максимальная актуальность данных |
| **Минусы:** Небольшая задержка обновления не критичных данных | **Минусы:** Высокая нагрузка на систему, неэффективен для редко изменяющихся данных |

**Заключение:** Гибридная стратегия оптимальна для текущей ситуации, так как обеспечивает компромисс между актуальностью критичных данных (статусы заказов) и производительностью системы при росте нагрузки.
