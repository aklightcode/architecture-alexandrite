Задание 2. Мониторинг

**Мотивация**

Внедрение системы мониторинга критически важно для бизнеса. Отсутствие видимости работы системы приводит к прямым финансовым потерям из-за срыва контрактов и ухудшения клиентского опыта. Мониторинг позволит:
- Оперативно выявлять точки отказа, где теряются заказы
- Объективно измерять соблюдение SLA по срокам выполнения
- Определять узкие места, влияющие на производительность
- Прогнозировать необходимость масштабирования ресурсов
- Снизить время простоя и обнаружения проблем

**Выбор подхода к мониторингу**

Для различных компонентов системы применяются разные подходы:

- **MES (Manufacturing Execution System)**: Методология **USE** (Utilization, Saturation, Errors)
- **Бэкенд-сервисы (онлайн-магазин, CRM)**: **Четыре золотых сигнала** (Latency, Traffic, Errors, Saturation)

**Метрики для мониторинга**

- **Number of requests (RPS) for API** - важно знать сколько запросов отрабатывает каждый API
- **Number of dead-letter-exchange letters in RabbitMQ** - количество повторных отправлений RabbitMQ важная метрика
- **CPU % for MES API** - мониторинг нагрузки при расчёте сложных моделей
- **Memory Utilisation for MES API** - контроль использования ресурсов нагруженного сервиса
- **Response time (latency) for API** - обеспечение качества пользовательского опыта
- **Size of S3 storage** - предотвращение остановки системы из-за нехватки места
- **Number of HTTP 500 API** - обнаружение критических сбоев в работе системы

**План действий**

1. **Развертывание инфраструктуры мониторинга**
    - Установка Prometheus для сбора метрик
    - Развертывание Grafana для визуализации
    - Настройка Grafana Alerting

2. **Инструментирование приложений**
    - Внедрение метрик для ключевых бизнес-процессов
    - Настройка сбора метрик со всех компонентов системы
    - Создание дашбордов с ключевыми метриками

**Критические показатели для алертинга:**

- **CPU % for MES API** - перегрузка инстанса при длительном значении ≥100%
- **Number of HTTP 500** - необходимость немедленного расследования при появлении ошибок
- **Memory Utilisation** - повод для реагирования при постоянной нагрузке ≥80%
- **Number of dead-letter-exchange letters** - значение >0 требует немедленного внимания
- **Response time latency** - превышение пороговых значений для критичных API
