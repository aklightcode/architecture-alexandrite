Задание 3. Трейсинг

**Мотивация**

Внедрение трейсинга необходимо для решения критических бизнес-проблем компании "Александрит". Трейсинг позволит:

**Технические преимущества:**
- Выявление точек отказа и зависания заказов в распределенной системе
- Определение компонентов с высокой латентностью
- Анализ производительности цепочек вызовов между микросервисами
- Оптимизация времени отклика системы

**Бизнес-метрики:**
- Снижение процента потерянных заказов
- Улучшение соблюдения SLA сроков выполнения заказов
- Повышение клиентской удовлетворенности (NPS)
- Сокращение времени расследования инцидентов
- Увеличение пропускной способности системы

**Предлагаемое решение**

**Архитектура трейсинга:**
- Каждый входящий API-запрос получает уникальный X-Trace-ID
- Фиксация временных меток на всех этапах обработки запроса
- Классификация запросов по типам: order, calculation, mqin, mqout
- Сбор контекстной информации: user GUID, IP, environment

**Схема архитектуры:**

**Компромиссы**

**Ограничения внедрения:**
- MES затрудняет прямое инструментирование кода
- Интеграция с RabbitMQ требует дополнительных затрат на разработку
- Высокая стоимость внедрения для legacy-компонентов
- Ограниченная полезность для синхронных вызовов внутри одного сервиса

**Экономические аспекты:**
- Стоимость инструментирования MES может превысить выгоду
- Обучение команды работе с новой системой мониторинга
- Затраты на инфраструктуру для хранения и обработки трейсов

**Аспекты безопасности**

**Меры защиты:**
- Доступ к данным трейсинга только через корпоративный VPN
- Двухфакторная аутентификация (2FA) для всех пользователей
- RBAC (Role-Based Access Control) с минимальными привилегиями
- Шифрование данных трейсинга при передаче и хранении
- Регулярный аудит доступа и мониторинг подозрительной активности

**Дополнительное задание**

**Автоматический мониторинг заказов:**
- Реализация автоматического отслеживания времени прохождения заказа по статусам
- Настройка алертинга при превышении лимитов времени на каждом этапе
- Интеграция с системой инцидент-менеджмента
